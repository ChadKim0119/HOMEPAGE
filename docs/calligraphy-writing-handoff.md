# 붓글씨 쓰기 애니메이션 핸드오프 — 信頼 · 安心 · 安全 · 便利

이 문서는 여백(Yeobaek) 홈페이지의 **캘리그라피 쓰기 애니메이션**을 다른 웹사이트(예: 토요타 진척보고회 자료 구축 사이트)에 그대로 옮겨 쓰기 위한 인계 문서입니다. 네 단어 **信頼(신뢰) · 安心(안심) · 安全(안전) · 便利(편리)** 의 획순은 [Arch Chinese 필순 12규칙](https://archchinese.com/chinese_stroke_order_rules.html)을 따릅니다.

- 대상: 프런트엔드 개발자, 디자이너, QA
- 의존성: 없음 (바닐라 JS, WebGL2, WebGL2가 없으면 2D 캔버스로 대체)
- 원본 저장소: `ChadKim0119/HOMEPAGE` — `src/strokes.js`, `src/writing.js`, `src/stroke-plans.js`, `src/compare.js`(`extractInk`)

## 1. 무엇을 하는가

스캔하거나 촬영한 붓글씨 이미지를 받아, **실제 붓으로 쓰는 순서와 움직임대로** 한 획씩 써 내려가는 애니메이션을 만듭니다. 마지막 프레임은 항상 원본 작품과 픽셀 단위로 같습니다.

원리는 After Effects의 "마스크 + Stroke(원본 이미지 드러내기)" 쓰기 기법과 같습니다. 다만 마스크 경로를 손으로 그리는 대신, 이미지에서 계산하거나 **획 계획(stroke plan)** 데이터로 지정합니다.

| 단계 | 하는 일 | 파일 |
|---|---|---|
| 1. 종이 제거 | 종이 색을 테두리에서 추정해 투명하게 만들고 먹선만 남김(낙관 색 유지) | `compare.js` `extractInk()` |
| 2. 획 복원 | 세선화(Zhang–Suen) → 중심선 그래프 → 붓 자국 잔가지 제거 → 꺾임에서 분할·접합 → 획순 | `strokes.js` `analyzeInk()` |
| 3. 획 계획 적용 | 작품에 맞는 계획이 있으면 그 순서·경로를 사용(중심선에 자동 정렬) | `stroke-plans.js` |
| 4. 한 획 = 한 번의 붓질 | 각 획이 실제로 덮은 먹(중심선 + 그 지점의 붓 두께 원)을 쓰는 순서대로 차지 | `strokes.js` `assignPixels()` |
| 5. 시간 지도 → 렌더 | 픽셀마다 붓이 닿는 시각을 계산하고, WebGL 셰이더가 그 시각에 원본 먹을 드러냄 | `writing.js` `Writer` |

### 왜 "그림 그리듯" 보이지 않는가
- 획을 선으로 덧칠하지 않습니다. 각 먹 픽셀이 **어느 획의 어느 지점**인지 정해져 있어서, 붓끝이 지나가는 순간 획의 **전체 폭이 한 번에** 나타납니다.
- 두 획이 겹친 먹은 **먼저 쓴 획**에 속합니다. 그래서 나중 획이 위에 다시 칠하지 않습니다.
- 붓이 닿은 자리·꺾인 자리에 뭉친 먹(기필·수필 덩어리)은 별도 획이 아니라 그 획의 일부로 처리합니다. 판정 기준은 그 지점의 붓 두께입니다.
- 행서의 연결선(連筆)은 붓을 떼지 않는 하나의 흐름으로 이어 씁니다.

## 2. 필순 규칙 (Arch Chinese 12규칙)과 엔진 반영

| # | 규칙 | 예 | 엔진 반영 |
|---|---|---|---|
| 1 | 위 → 아래 | 二, 早 | 겹치는 부분은 위 먼저 |
| 2 | 왼쪽 → 오른쪽 | 川, 好 | 나란한 부분은 왼쪽 먼저 |
| 3 | 가로 먼저, 세로 나중 | 十, 王 | 교차하면 가로 먼저 |
| 4 | 삐침(撇) 먼저, 파임(捺) 나중 | 人, 大 | 교차·접촉 시 왼쪽으로 내려가는 획 먼저 |
| 5 | 바깥 먼저, 안 나중 | 同, 月 | 둘러싸는 획 먼저 |
| 6 | 안 먼저, 바깥 나중 | 凶, 这 | (辶·廴 받침) — 획 계획으로 지정 |
| 7 | 안을 채우고 아래를 닫음 | 口, 日, 国 | 상자를 닫는 아래 가로는 마지막 |
| 8 | 가운데 먼저, 양쪽 나중 | 小, 水, 永 | 위 점 → 가운데 → 왼쪽 날개 → 오른쪽 날개 |
| 9 | 꿰뚫는 획은 마지막 | 中, 羊 | 여러 가로를 관통하는 세로는 그 뒤에 |
| 10 | 왼쪽 세로 먼저, 둘러싸기 나중 | 口, 日 | 같은 모서리에서 시작하면 │ 먼저, 𠃍 나중 |
| 11 | 위·왼쪽 위의 점은 먼저 | 衣, 永 | 짧은 점이 위·왼쪽이면 먼저 |
| 12 | 안·오른쪽 위의 점은 나중 | 我, 玉, 心 | 짧은 점이 안·오른쪽이면 나중 |

한글도 같은 원리(위→아래, 왼→오른, 초성→중성→종성, ㄱ·ㄴ은 꺾어서 한 획, ㅇ은 위에서 반시계)로 처리합니다.

## 3. 단어별 필순과 작품 흐름

각 표의 "표준 필순"은 교과서 획순입니다. "작품 흐름"은 이 작품(행서)에서 붓이 실제로 움직이는 단위입니다. 행서는 여러 획을 붓을 떼지 않고 이어 쓰므로, 움직임 수가 표준 획 수보다 적을 수 있습니다.

### 3-1. 安心 (안심) — 표준 10획 · 작품 9동작 · **검증 완료**

| 글자 | 표준 필순 |
|---|---|
| 安 (6) | 丶 → 丶 → ㇇ → ㄑ(㇛) → 丿 → 一 |
| 心 (4) | 丶 → ㇂(와구) → 丶 → 丶 |

| 순서 | 작품 흐름 | 포함 표준 획 | 규칙 |
|---|---|---|---|
| 1 | 宀 위 점 | 丶 | 1, 11 |
| 2 | 왼쪽 점 → 긴 가로 → 갈고리 (한 번에) | 丶 ㇇ | 11, 2 |
| 3 | 女 삐침점 (위에서 내려와 아래로 꺾임) | ㄑ | 1, 4 |
| 4 | 女 삐침 (오른쪽 위 → 왼쪽 끝 → 꺾임) | 丿 | 4 |
| 5 | 女 가로 → 가는 연결선 | 一 | 1, 2 |
| 6 | 心 첫 점 (5에서 붓을 떼지 않고 이어짐) | 丶 | 11 |
| 7 | 心 와구 (갈고리 포함) | ㇂ | 2 |
| 8 | 心 가운데 점 | 丶 | 12 |
| 9 | 心 오른쪽 점 (8에서 연결선으로 이어짐) | 丶 | 12 |

### 3-2. 信頼 (신뢰) — 표준 25획 · 작품 21동작 · 초안

| 글자 | 표준 필순 |
|---|---|
| 信 (9) | 丿 → 丨 → 丶 → 一 → 一 → 一 → 丨 → 𠃍 → 一 |
| 頼 (16) | 束: 一 → 丨 → 𠃍 → 一 → 丨 → 丿 → 丶 · 頁: 一 → 丿 → 丨 → 𠃍 → 一 → 一 → 一 → 丿 → 丶 |

작품 흐름: 亻(丿, 丨) → 言 점 → 言 첫 가로 → 言 두·세 번째 가로(연필) → 口 왼쪽 세로 → 口 꺾음+닫기 → 束 가로 → 束 口(세로·꺾음·닫기) → 束 꿰뚫는 세로(규칙 9) → 束 삐침·점 → 頁 첫 가로+삐침 → 目(세로·꺾음·안 가로·닫기) → 頁 왼 다리 → 頁 오른 다리.

### 3-3. 安全 (안전) — 표준 12획 · 작품 9동작 · 초안

| 글자 | 표준 필순 |
|---|---|
| 安 (6) | 丶 → 丶 → ㇇ → ㄑ → 丿 → 一 |
| 全 (6) | 丿 → ㇏ → 一 → 一 → 丨 → 一 |

작품 흐름: 宀 점 → 宀 점+가로 갈고리 → 女 ㄑ → 女 丿 → 女 一(고리 모양, 全으로 연결) → 人 삐침(연필) → 人 파임(규칙 4) → 王 가로·가로·세로(연필) → 王 아래 가로(마지막).

### 3-4. 便利 (편리) — 표준 16획 · 작품 16동작 · 초안

| 글자 | 표준 필순 |
|---|---|
| 便 (9) | 丿 → 丨 → 一 → 丨 → 𠃍 → 一 → 一 → 丿 → ㇏ |
| 利 (7) | 丿 → 一 → 丨 → 丿 → 丶 → 丨 → 亅 |

작품 흐름: 亻(丿, 丨) → 更 첫 가로 → 曰(왼쪽 세로 → 꺾음 → 가운데 가로 → 닫기, 규칙 10·7) → 更 삐침 → 更 긴 파임 → 禾(삐침 → 가로 → 세로 → 삐침 → 점, 규칙 3·4·8) → 刂(짧은 세로 → 갈고리).

> **상태:** 安心은 실제 작품으로 검증했습니다. 信頼·安全·便利는 공유된 이미지를 보고 작성한 **초안**입니다. 원본 이미지 파일로 경로를 맞춘 뒤 `status: 'verified'`로 바꾸세요(5장 참고). 초안이 작품과 맞지 않으면 엔진이 계획을 적용하지 않고 자동 분석으로 돌아가므로, 엉뚱하게 그려지지는 않습니다.

## 4. 통합 가이드 (다른 사이트에 붙이기)

### 4-1. 파일 복사
`src/strokes.js`, `src/writing.js`, `src/stroke-plans.js`를 그대로 복사합니다. 종이 바탕이 있는 스캔을 쓴다면 `src/compare.js`의 `extractInk()`도 함께 복사합니다. 모두 ES 모듈이고 외부 의존성이 없습니다.

### 4-2. 최소 사용 예

```js
import { extractInk } from './compare.js';
import { analyzeInk } from './strokes.js';
import { Writer } from './writing.js';

// 1) 종이 바탕 제거 (이미 투명 PNG면 그대로 반환)
const response = await fetch('/assets/anshin.jpg');
const ink = await extractInk(await response.blob());
const href = URL.createObjectURL(ink);

// 2) 획 분석 (작품에 맞는 획 계획이 있으면 자동 적용) — 0.2~0.5초, 결과는 재사용
const analysis = await analyzeInk(href);
console.log(analysis.plan); // { id: 'anshin', word: '安心', status: 'verified' } 또는 null

// 3) 쓰기
const writer = new Writer(analysis, 'brush', {
  href,
  dark: false,          // 어두운 배경이면 true (먹을 밝게)
  reduced: matchMedia('(prefers-reduced-motion: reduce)').matches,
  onDone: () => {},     // 완료 콜백
});
await writer.ready;
container.append(writer.element);   // <canvas>
writer.size(container.clientWidth, container.clientHeight); // 비율 유지(contain)
writer.play();

// 화면에서 뺄 때 반드시 정리 (브라우저 WebGL 컨텍스트 수 제한 대비)
writer.destroy();
```

### 4-3. 옵션

| 옵션 | 기본 | 설명 |
|---|---|---|
| 효과 (2번째 인자) | `'brush'` | `brush` 붓 · `pen` 펜 · `bleed` 먹 번짐 · `dry` 갈필 · `light` 빛의 획 |
| `target` | `1` | 속도 배율. `0.4`면 약 2.5배 빠름(미리보기용) |
| `loop` | `false` | 반복 재생 |
| `dark` | `false` | 어두운 배경용 밝은 먹 |
| `reduced` | `false` | 동작 줄이기: 즉시 완성 화면 |

### 4-4. 진척보고회 자료 사이트 적용 권장
- **슬라이드/섹션 진입 시 재생**: `IntersectionObserver`로 화면에 들어올 때 `play()`, 나갈 때 `destroy()`.
- **에셋 준비**: 가능하면 배경이 투명한 PNG로 납품받습니다(종이 제거 단계 생략·정확도↑). 해상도는 긴 변 1,200~2,400px을 권장합니다.
- **분석 캐시**: 같은 작품은 `analyzeInk` 결과를 메모리에 두고 재사용합니다.
- **동시 재생**: WebGL 컨텍스트는 페이지당 6개 이하로 유지하세요.
- **접근성**: 캔버스는 `aria-hidden`입니다. 옆에 단어와 뜻("安心 — 안심")을 텍스트로 함께 둡니다. `prefers-reduced-motion`을 존중합니다.

## 5. 획 계획(stroke plan) 작성·검증 방법

`src/stroke-plans.js`의 항목 하나가 작품 하나입니다.

```js
{
  id: 'anshin', word: '安心', ko: '안심', meaning: 'Peace of mind',
  status: 'verified' | 'draft',
  grid: { x0, y0, x1, y1 },  // 작품 이미지에서 먹이 차지하는 영역(픽셀)
  aspect: 2.118,             // grid를 0~1로 정규화했을 때만 필요
  strokes: [
    { char: '安', std: ['丶', '㇇'], name: '점 → 가로 갈고리', rules: [11, 2],
      flow: false,                // true면 앞 움직임에서 붓을 떼지 않음(연필)
      path: [[x, y], [x, y], …] }, // 붓이 실제로 지나가는 순서대로 중심선 좌표
  ],
}
```

작성 요령:
1. 원본 이미지를 이미지 편집기에서 열고, 먹 영역의 왼쪽 위·오른쪽 아래 좌표를 `grid`에 적습니다.
2. 표준 필순(3장) 순서대로, 각 움직임의 **중심선**을 시작점부터 끝점까지 4~10개 점으로 적습니다. 정확할 필요는 없습니다. 엔진이 각 점을 먹선 중심선에 자동으로 붙입니다(허용 오차: 작품 긴 변의 약 4.5%).
3. 붓을 떼지 않고 이어지는 움직임은 `flow: true`로 지정합니다.

적용 조건(자동 판정):
- 먹 영역 가로세로 비율이 계획과 ±16% 이내
- 계획 경로 점의 80% 이상이 먹 위(또는 중심선 근처)에 있음
- 먹 중심선의 70% 이상이 계획 경로 근처에 있음
- 여러 계획이 맞으면 점수(위 두 비율의 곱)가 가장 높은 계획을 씀 — 安心과 安全처럼 같은 글자를 공유해도 구분됩니다.

검증: 홈페이지의 "캘리그라피 비교하기"에 원본을 불러와 ▶(Space)로 재생합니다. 계획이 적용되면 "획 계획으로 씁니다: 安心"이 표시됩니다. 표시되지 않으면 경로가 먹에서 벗어난 것이므로 좌표를 고칩니다.

## 6. 타이밍

| 항목 | 값 |
|---|---|
| 전체 길이 | 획 수에 비례, 쓰기 2.4~5.6초 + 획 사이 쉼(최대 2.4초) |
| 획 사이 쉼 (붓) | 같은 글자 190ms · 다음 글자 380ms · 다음 줄 560ms |
| 연필(`flow`) | 쉼 없음, 일정 속도 |
| 속도 곡선 (붓) | 누르기 → 긋기 → 떼기 (ease-in-out 72% + linear 28%) |

## 7. 한계와 다음 단계
- 자동 분석의 획순은 추정입니다. 행초서처럼 획이 크게 뭉친 작품은 획 계획을 쓰는 것이 정확합니다.
- 信頼·安全·便利 계획은 원본 파일로 보정해야 합니다. 원본(가능하면 투명 PNG)을 받으면 경로를 맞춰 `verified`로 올립니다.
- 辶·廴 받침(규칙 6)은 자동 분석에서 다루지 않으므로 해당 글자는 획 계획으로 지정합니다.
